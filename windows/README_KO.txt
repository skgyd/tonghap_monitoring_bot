monitoringbot 1.4.6  |  Windows 단독 시연
========================================

1. monitoringbot.zip을 새 폴더에 풀거나, monitoringbot-part1.zip과 monitoringbot-part2.zip을 같은 상위 폴더에 풀어 내부 monitoringbot 폴더를 합치세요. 두 최신 분할 파일에는 생성기가 필요 없습니다.
   Windows 11 x64, Edge 또는 Chrome, 쓰기 가능한 로컬 폴더가 필요합니다.
   사용 권장 환경은 8 GB 메모리, 6 GB 이상 여유 공간입니다.
2. monitoringbot 폴더 안의 monitoringbot.exe를 실행하세요.
   운영자 웹 상단에서 1.4.6와 ‘시연 준비 완료’를 확인하세요. 서버·DB·수집기가 이 PC에서 실행됩니다.
   초기 이미지를 확인하고 새 회차용 디스크를 만드는 동안 몇 분이 걸릴 수 있습니다.
3. 운영자 웹의 ‘시연 화면 열기’에서 폴스타 열기, 잡패스 열기, 두 화면 함께 열기를 누르면 원본 화면이 새 탭에 열립니다.
   열람 자체로 오류가 생성되지는 않습니다. 운영자 웹 상단에 다섯 심사 계정이 바로 표시됩니다. ‘시연 준비 완료’ 후 ‘Mattermost 열기’를 눌러 로그인하세요.
   monitoring01 / Demo!1, monitoring02 / Demo!2, monitoring03 / Demo!3, monitoring04 / Demo!4, monitoring05 / Demo!5
   관제팀에서 /ib 화면을 입력해 좌측 폴스타, 우측 잡패스를 엽니다.
4. 운영자 웹의 ‘폴스타 오류 발생’ 또는 ‘잡패스 오류 발생’을 누르세요. 키 입력과 별도 EXE 실행은 없습니다.
   각 회차의 폴스타 첫 오류는 기업회계, 잡패스 첫 오류는 금융거래입니다. 기본 설정에서는 관제팀과 해당 업무 채널에 함께 게시됩니다.
   각 원본의 두 번째 클릭부터는 CMS·자동이체통합관리·온누리상품권정보교환·네트워크론 중 하나, 오류 내용은 매 클릭마다 원본별 6가지 중 하나가 선택됩니다.
   폴스타 심각도는 새 회차의 첫 오류부터 critical(분홍 행)과 major(노란 행)가 교대로 나타납니다.
   표시된 이벤트 ID로 원본 행과 채널 게시물을 대조하세요. 응답이 끊기면 같은 버튼으로 재시도합니다.
   수집기가 원본 화면을 읽고 캡처한 뒤 Mattermost에 전송합니다. 잡패스 오류 행을 더블클릭하면 상세 로그가 보입니다.
5. 원본 화면의 팀 경로는 IT운영팀(잡패스 02)과 결제개발팀(05)으로 구분합니다.
   채널 매핑에는 마지막 업무명을 사용합니다. 매핑이 없는 사건은 관제팀에 나타납니다.
   /ib 매핑 잡패스 CMS ~finance 는 앞으로 발생하는 CMS 오류의 담당 채널을 지정합니다.
   /ib 채널변경 실제사건ID ~finance 는 이미 발생한 한 건을 이관합니다.
   담당 채널에서 접수·완료를 누릅니다. 답글·이모지를 관제팀에서 확인하고 /ib 이력 실제사건ID로 처리 이력을 확인하세요.
6. 운영자 웹에서 ‘서버 종료’를 누르고 폐기를 확인하세요. 이번 회차의 디스크·DB·채팅·첨부·캡처·프로필·로그가 폐기됩니다.
   운영자 창과 이 앱이 연 전용 브라우저가 닫힌 뒤 정상 종료 메시지가 표시됩니다. 다음 실행은 기본 채널/매핑에서 시작합니다.
   탭만 닫았다면 서버는 계속 실행됩니다. 같은 monitoringbot.exe를 다시 열어 해당 회차로 복귀할 수 있습니다.

운영 파일은 실행 폴더의 work/sessions/<회차 ID>/ 아래에서만 사용합니다. 읽기 전용 초기 이미지 및 기존 data는 보존합니다.
정리 실패가 표시되면 전용 브라우저가 닫혔는지 확인하고 다시 실행하세요. 소유권을 확인하지 못한 폴더는 자동 삭제하지 않습니다.
시연용 심사 계정은 매 회차 같은 아이디와 비밀번호를 사용합니다. 관리자 자격과 회차 데이터는 배포 ZIP에 포함하지 않습니다.

선택 Windows 수락시험: 서버가 꺼진 상태에서 VERIFY-WINDOWS.cmd를 실행하세요. 검증기가 전용 회차 두 개를 시작·종료하고
실제 브라우저 버튼, 원본, Mattermost 캡처/접수·완료·이관/답글 및 다음 회차 초기화를 검사합니다. 부팅 두 번의 시간이 필요합니다.
